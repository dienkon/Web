## 2. RENDERING STACK IDENTIFICATION

The current application renders its scene via **React Three Fiber (v9.6.1) on Three.js (r185.1)** using a full 3D WebGL2 canvas context (`<Canvas>` in `src/components/three/LabScene.tsx`). The UI is composed of DOM + TailwindCSS overlays situated above and around the WebGL canvas.

### 2.1 Glassware Drawing (`Beaker`, `Flask`, `TestTube`, `GraduatedCylinder`)
- **Geometry:** Procedural `LatheGeometry` generated from 2D profile curves (`createVesselLatheGeometry` in `src/vfx/materials/glass.ts`).
  - Beaker: Cylindrical body with slight lip flare and bottom fillet (32 radial segments).
  - Erlenmeyer Flask: Conical lower trunk transitioning into a cylindrical neck.
  - Test Tube: High-aspect cylinder terminating in a hemispherical rounded bottom.
  - Graduated Cylinder: Slender tall cylinder with a hexagonal base pedestal.
- **Glass Material:** Borosilicate glass simulated via two passes:
  - *Front face:* `MeshPhysicalMaterial` (`roughness: 0.03`, `metalness: 0.05`, `clearcoat: 1.0`, `specularIntensity: 1.0`, `depthWrite: false`) with a custom GLSL fragment hook in `onBeforeCompile` that adds a view-dependent Fresnel rim highlight:
    $$\text{Fresnel} = (1 - |\vec{v} \cdot \vec{n}|)^{2.6} \times 0.85$$
  - *Back face:* Inner glass reflection pass with lower opacity (`0.18`).
- **Graduations & Decals:** Textured transparent cylindrical decals (`VesselGraduations` in `Vessels.tsx`) mapped with procedurally generated high-resolution graduation ticks and volume labels (`getVesselGraduationTexture`).

### 2.2 Liquid Drawing
- **Mesh:** A cloned inner lathe geometry (`createVesselLatheGeometry().inner`).
- **Orientation & Clipping:** A dynamic `THREE.Plane` with normal $(0, -1, 0)$ is passed to `material.clippingPlanes`. The plane's constant is dynamically computed based on the fill fraction and adjusted by multiplying with the vessel's inverse orientation quaternion (`_scratchQuat.copy(vesselMesh.quaternion).invert()`). This ensures the liquid surface **strictly stays level relative to world gravity $(0, -1, 0)$** regardless of how the vessel is tilted or rotated.
- **Shader:** `RealisticLiquid` (`src/vfx/materials/liquid.tsx`) overrides `MeshPhysicalMaterial` shaders via `onBeforeCompile`:
  - Displaces vertices along surface waves using Simplex noise modulated by `uSloshSpeed` and `uPourAgitation`.
  - Injects turbidity (`uTurbidity`) to model light extinction in milky precipitates.
  - Applies local mixing sphere blending (`uMixingPoint`, `uMixingRadius`, `uMixingColor`) to display localized reagent plumes before homogenization.
- **Caustics & Table Shadow:** A plane quad below each vessel displays an animated caustic texture (`getCausticTexture`) whose brightness and color are modulated by the liquid's transmittance.

### 2.3 Reagent Bottles & Solids
- **Bottles:** Procedural lathe/cylinder geometries with amber/flint glass materials, ground-glass stoppers, and canvas-rendered GHS chemical safety labels (`Bottle` in `Vessels.tsx`).
- **Solids:** `SolidContentsRenderer.tsx` renders distinct 3D morphologies:
  - *Powders ($CaCO_3, MnO_2, Cu(OH)_2$):* Conical pile geometry with surface noise.
  - *Metals ($Fe, Cu, Zn, Mg$):* Shiny metallic granules or ribbons with high metalness ($0.85$) and low roughness.
  - *Crystals ($NaCl, PbI_2$):* Instanced cubic and icosahedral polyhedra with faceted specular glints.

### 2.4 Pouring Stream
- `PhysicalStreamRenderer.tsx` generates a dynamic parametric ribbon/tube mesh following a ballistic parabola from the vessel lip to the target:
  $$\vec{r}(t) = \vec{r}_0 + \vec{v}_0 t + \frac{1}{2} \vec{g} t^2$$
  The tube diameter contracts as the fluid accelerates under gravity according to mass continuity ($A(s) \propto 1/v(s)$). At flow rates $< 1.2\text{ mL/s}$, the continuous stream transitions into spaced Rayleigh-Plateau droplet quads.

## 3. STATE MODEL & SIMULATION LOOP

### 3.1 State Storage
State is centralized in Zustand (`src/store/useAppStore.ts`):
```typescript
interface VesselState {
  id: string;
  name: string;
  type: VesselType;
  capacity_ml: number;
  position: [number, number, number];
  rotationY: number;
  substances: string[];         // Formula keys present (e.g. ['CuSO4', 'NaOH'])
  contents: SubstanceContent[]; // Detailed vector: formula, moles, mass_g, volume_ml, concentration_M
  volume: number;               // Normalized 0 to 1
  volume_ml: number;            // Total liquid volume in mL
  mass_g: number;               // Total mass in grams
  density_g_ml?: number;
  temperature_c: number;        // Lumped vessel temperature (°C)
  ph: number;                   // 0 to 14
  liquidColor?: string;         // Hex color
  liquidOpacity?: number;
  hasPrecipitate: boolean;
  precipitateColor?: string;
  precipitateAmount_g?: number;
  isBoiling: boolean;
  boilingIntensity?: number;
  hasGas: boolean;
  gasColor?: string;
  gasRate?: number;
  foam_ml?: number;
  isExplosion?: boolean;
}
```

### 3.2 Main Game / Simulation Loop
Execution is driven by Three.js `requestAnimationFrame` via React Three Fiber's `useFrame`:
1. In `src/components/three/LabScene.tsx`, `<SimulationTicker />` runs every frame:
   ```typescript
   useFrame((_, delta) => {
     tickSimulation(delta);
     PourController.tick(delta, state.vessels, state.isSimulationPaused, state.timeScale);
   });
   ```
2. `useAppStore.getState().tickSimulation(dt)` executes at frame rate:
   - Burns fuel in active burners (`fuelLevel_ml -= burnRate * dt`).
   - Computes thermal conduction from burners to nearby vessels based on 3D distance and wire-gauze alignment.
   - Computes Newtonian cooling to ambient ($25^\circ\text{C}$):
     $$\frac{dT}{dt} = \frac{P_{in} - h A (T - T_{amb})}{C_{total}}$$
   - Advances active kinetics progress ($0 \to 1$) over scripted durations.
3. In `src/simulation/render/PhysicalSimulationRenderer.tsx`, a secondary `useFrame` invokes:
   ```typescript
   mgr.step(vessel, dt, { heatPower_W, agitation, ... });
   ```
   This updates the local `BoilingSystem`, `EvaporationSystem`, and `PrecipitationSystem` particle positions and sediment bed height.

### 3.3 Reaction Triggering Mechanism
- **Trigger:** Adding a chemical or pouring liquid into a vessel calls `addChemicalToVessel` or `mixSubstances` in `useAppStore.ts`.
- **Matching:** `evaluateLocalChemistry` in `src/engine/chemistryEngine.ts` scans the static array `DETERMINISTIC_REACTIONS` (20 reactions).
- **Matching Logic:** `matchesReactants` checks if all required chemical formula tokens exist in `vessel.substances`.
- **Result:** Returns a `MixResult` containing an array of static effects:
  ```typescript
  effects: [
    { type: 'PRECIPITATE', duration: 3, color: '#ffffff' },
    { type: 'GAS', duration: 4, color: '#fef08a' },
    { type: 'BOIL', duration: 5 },
    { type: 'COLOR_CHANGE', duration: 2, color: '#ec4899' }
  ]
  ```
- **Limitation:** The current trigger is a **discrete lookup** with fixed durations ($3\text{ s}, 4\text{ s}, 5\text{ s}$). If the user adds twice as much acid, the duration does not scale with chemical stoichiometry; if the vessel is cooled, the reaction does not slow down; and mixing is instantaneous throughout the entire vessel volume.

## 6. EXISTING EFFECTS AUDIT & QUALITY DEFICIENCIES

| Effect | Current Implementation | Underlying Mechanism | Quality Issues & Realism Deficiencies |
|---|---|---|---|
| **Boiling** | `BoilingSystem.ts` + `Bubbles.tsx` | 5 temperature thresholds spawn `PhysicalBubble` JS objects (max 90). Buoyancy + Stokes rise. | **1.** No spatial velocity field; bubbles rise in straight lines without fluid circulation. **2.** No subcooled bubble collapse ("singing" stage). **3.** Bubble size distribution does not follow Fritz departure equation. **4.** Temperature does not naturally plateau at $100^\circ\text{C}$ through latent heat absorption. |
| **Evaporation & Steam** | `EvaporationSystem.ts` + `Steam.tsx` | Evaporates volume via empirical rate; spawns billboard sprite particles drifting upwards. | **1.** Billboards lack volumetric scattering. **2.** No "invisible gap" of dry vapor directly above the water surface before condensation. **3.** No condensation film or droplets on the upper glass walls. **4.** No sliding droplets with trail clearing. |
| **Precipitation** | `PrecipitationSystem.ts` + `Precipitate.tsx` | If $C > C_s$, spawns flakes drifting down; accumulates into flat disk `SedimentMesh`. | **1.** Forms uniformly throughout the beaker rather than at the fluid mixing front / filaments. **2.** No classical nucleation rate equation ($J(S)$). **3.** Sediment bed lacks angle of repose and shear resuspension from stirring. **4.** PbI2 "golden rain" lacks tumbling plate crystal dynamics. |
| **Color & Mixing** | `mixing.ts` + `liquid.tsx` | Beer-Lambert color interpolation in linear RGB. Local mixing sphere uniform (`uMixingPoint`). | **1.** Linear RGB fails on subtractive spectral mixing (e.g. blue + yellow can turn grey instead of vibrant green). **2.** No 2D/3D advection-diffusion fluid grid; mixing is smoothed by an artificial radial lerp. |
| **Gas Evolution / Fizz** | `GasPlume.tsx` + `Bubbles.tsx` | Spawns bubble particles from bottom and gas plume billboards above rim. | **1.** Bubbles spawn from bulk liquid rather than nucleating on solid reactant surfaces (e.g. on Zn granules or marble chips). **2.** Produced gas does not displace volume ($nRT/P$). **3.** Heavy gases ($CO_2, NO_2$) do not spill over the beaker rim and sink onto the table. |
| **Flames & Combustion** | `flame.tsx` + `flameShader.ts` | Displaced cone mesh with Simplex noise. Point light on workbench. | **1.** Scripted shader displacement, not buoyant combustion fluid simulation. **2.** No blackbody Planck radiation curve. **3.** No flame test emission spectrum lines (Na 589nm, Cu green, K lilac). |
| **Dissolving & Solids** | `SolidContentsRenderer.tsx` + `SolidParticles` | Fixed-count instanced polyhedra (16 items) scaling down uniformly by $(1 - progress)$. | **1.** Does not follow Noyes-Whitney mass transfer kinetics. **2.** No dense solution plume ("blue rivers" sinking from dissolving crystal). **3.** No Schlieren density gradient refraction. |
| **Audio** | `src/utils/audio.ts` + `PourAudio.ts` | Web Audio API bandpass noise and oscillators triggered by UI events. | **1.** Bubbles do not follow Minnaert resonance frequency ($f \approx 3.26/R$). **2.** Boiling sound does not transition smoothly through simmering, singing, and rolling boil based on physical state. |

## 8. RISK LIST & MIGRATION STRATEGY

### 8.1 Identified Risks
1. **Zustand Store Coupling:** `src/store/useAppStore.ts` is 1,995 lines and acts as the central hub for all UI panels. Rewriting it directly risks breaking modals, titration curves, and undo/redo snapshots.
2. **TypeScript Compilation Errors:** Existing files (`KineticsEngine.ts`, `SimulationDebugPanel.tsx`, `SimulationDebugGizmos.tsx`, `LabReportModal.tsx`) contain minor TypeScript compile errors from earlier development that fail `tsc --noEmit`.
3. **Headless Execution Compatibility:** Unit tests in Vitest run under Node where `window`, `HTMLCanvasElement`, and WebGL contexts do not exist by default.
4. **Performance on Integrated GPUs:** A full 2D/3D Stable-Fluids grid and large particle counts can exceed the 16.6ms frame budget on low-end laptops if allocated dynamically.

### 8.2 Migration Strategy
1. **Fix Compile Baseline (Immediate Pre-flight):** Resolve the pre-existing TypeScript lint errors in `KineticsEngine.ts`, `SimulationDebugPanel.tsx`, etc., ensuring `npm run lint` and `npm run test` pass cleanly.
2. **Clean Separation of Simulation Core (`src/core/`, `src/chem/`, `src/sim/`):**
   - The simulation core will have **zero DOM and zero R3F dependencies**. It operates exclusively with standard numbers, vectors, and typed arrays.
   - This guarantees it can be executed headless in Vitest under Node for rigorous invariant testing (mass, energy, charge conservation).
3. **Dual-Engine Feature Flag (`?engine=v2`):**
   - Provide an engine selector URL parameter (`?engine=v2` or `?engine=v1`) and a toggle in the settings panel.
   - When `engine=v2` (default), the new coupled physical simulation engine runs.
   - When `engine=v1`, the legacy deterministic lookup table and timeline VFX run.
4. **Legacy Store Adapter (`src/adapters/legacy.ts`):**
   - An adapter bridge reads from the new `SimulationEngine` and publishes synchronized updates to `VesselState` (volume, temperature, pH, precipitate amount, boiling status) at 20–30 Hz.
   - All existing UI components (`VesselInspector`, `MeasurementHUD`, `TitrationPanel`, `LabReportModal`) continue to function without modifying their internal logic.

## 9. DECISION RECORD — RENDER TIERING

### 9.1 Context Identification
The scene already uses a **WebGL2** context provided by Three.js `WebGLRenderer` in `<Canvas gl={{ antialias: true, alpha: true, powerPreference: 'high-performance' }}>`.

### 9.2 Capability Detection Implementation (`src/render/gl.js` / `gl.ts`)
On startup, a probe queries the active WebGL2 context:
- Context type: `webgl2` vs `webgl`
- Extensions:
  - `EXT_color_buffer_float` (required for floating-point ping-pong simulation textures RGBA16F / RGBA32F)
  - `OES_texture_float_linear` (for smooth bilinear hardware filtering on simulation grids)
  - `EXT_float_blend`
- Device parameters: `MAX_TEXTURE_SIZE`, `MAX_VERTEX_UNIFORM_VECTORS`, GPU unmasked renderer string.

### 9.3 Quality Tier Allocation Table
| Feature | Tier A (High Quality) | Tier B (Medium Quality) | Tier C (Low / Mobile Fallback) |
|---|---|---|---|
| **Target Hardware** | Desktop dGPU / Modern Apple Silicon / Fast iGPU | Typical Laptop iGPU (Intel Iris, AMD Radeon) | Mobile phones, battery-saver mode, fallback |
| **Fluid Field** | GPU Stable-Fluids ping-pong grid ($128 \times 192$) | GPU/CPU 2D slice ($96 \times 144$) | CPU typed array grid ($48 \times 72$) @ 30 Hz |
| **Particles Cap** | Up to 60,000 active particles (InstancedMesh) | Up to 20,000 active particles | Up to 4,000 active particles |
| **Liquid Shading** | Full Beer-Lambert absorption + refractive Fresnel + dynamic caustic plane + surface height-field | Analytic Beer-Lambert depth absorption + screen-space refraction | Standard material gradient + static meniscus disk |
| **Steam / Vapor** | Volumetric billboard slices with Henyey-Greenstein forward scattering | Multi-particle soft sprites with curl turbulence | Simplified opacity particles |
| **Post-Processing** | ACES Filmic + Bloom + Heat-Haze UV distortion | Bloom + subtle vignette | No post-processing passes |

### 9.4 Dynamic Adaptive Tier Switching
- A moving window tracks the average frame render time over 120 frames ($2\text{ seconds}$ at 60 FPS).
- If frame time $> 22\text{ ms}$ ($< 45\text{ FPS}$) for $> 2.0\text{ seconds}$, degrade quality by one step (disable heat haze $\to$ reduce particle pool cap $\to$ drop grid resolution).
- If frame time $< 12\text{ ms}$ ($> 80\text{ FPS}$) consistently for $> 5.0\text{ seconds}$, step up quality tier.
- A $5.0\text{-second}$ hysteresis cooldown prevents rapid oscillation.
