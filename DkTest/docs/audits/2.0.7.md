## Root Causes & Findings

- **Cloudinary PDF failure (`HTTP 401 deny or ACL failure`)**: Live verification against cloud `dys3wgutz` (`comic_raw_files_preset`) showed that uploading `.pdf` files via `/auto/upload` or `/raw/upload` with a `.pdf` public_id suffix causes Cloudinary Free-tier ACL rules to reject direct `.pdf` delivery with `HTTP 401`. Conversely:
  1. Uploading raw PDF bytes to `/raw/upload` with an **extensionless blob filename** (`dkdoc_<timestamp>_<slug>`) and appending `?dkext=pdf&dkname=<filename>` returns **HTTP 200 OK**, `Access-Control-Allow-Origin: *`, and byte-for-byte lossless `%PDF-1.x` data.
  2. Previously uploaded legacy `res.cloudinary.com/.../image/upload/.../*.pdf` assets still serve high-resolution page images (`pg_1,w_1600,q_auto:good,f_jpg/.../*.jpg`) with **HTTP 200 OK** and expose total page count via `Access-Control-Expose-Headers: X-Cld-Error` (`Image only has N pages`).
- **Android WebView PDF opening & downloading failure**: Standard Android WebViews neither render cross-origin `<iframe src="...pdf">` documents inline nor process `blob:` / `<a download>` links without a native Capacitor bridge or `DownloadListener`.
- **Read-budget risk for massive repositories**: Storing 4,000+ catalog items solely as individual Firestore documents queried per user visit would consume thousands of Firestore reads per browsing session. Separating the 4,180 pre-populated items into a compressed static CDN seed (`public/data/document-library-seed.json`, ~472 KB gzipped) plus a 45s RAM-cached live delta endpoint (`/api/documents/live`) reduces browsing/searching Firestore reads to **0 per client interaction**.

## Firestore Read & Write Budget

- **Browsing, filtering & searching 4,180+ seeded documents**: **0 Firestore reads** — served from static CDN `/data/document-library-seed.json` and filtered in-memory in `<5ms`.
- **Live Admin & Community uploads overlay (`GET /api/documents/live`)**: Cached in server memory for **45 seconds** (`LIVE_DOCS_TTL_MS`) and client memory for **30 seconds**, invalidated immediately on write — at most **1 Firestore query per 45s across all concurrent users**.
- **Bookmarks (`Đã lưu`)**: Stored locally in `localStorage` (`dktest:saved_document_ids`) — **0 Firestore reads/writes**.
- **Social Open Graph crawlers (`/documents`, `/documents/doc_...`)**: Resolved directly from the server's in-memory seed map for all 4,180 seeded documents (**0 Firestore reads**); only live `ldoc_...` documents perform **1 single `doc.get()`**.
- **Unlocking a paid document**: **1 atomic Firestore transaction** updating buyer wallet, optional creator wallet revenue share, transaction ledger, and `library_entitlements/{uid}_{docId}`.

## Security Boundaries

- **Paid document file isolation**: Whenever `accessMode == 'paid'` and `priceVnd > 0`, `createOrUpdateLibraryDocument` strips `fileUrl`, `answerUrl`, `videoUrl`, and `subFiles` from `library_documents/{docId}` and stores them exclusively in `library_document_secrets/{docId}`.
- **Firestore Rules enforcement**:
  - `library_documents/{docId}`: blocks client writes by non-admins and rejects even admin writes that attempt to embed `fileUrl`, `answerUrl`, or `subFiles` on a paid document.
  - `library_document_secrets/{docId}`: strictly `allow read, write: if isAdmin();` — inaccessible to anonymous users and students (verified in Firebase Emulator rules suite).
  - `library_entitlements/{entId}`: owner/admin read only; admin/server write only.
- **Safe locked previews**: Locked paid PDFs only expose 1–2 pre-rendered sample page JPEGs (`previewImageUrls`) on Cloudinary `image/upload`; the full PDF binary URL is never transmitted until `checkDocumentAccess` confirms an active entitlement, authorship, or admin role.
- **SSRF-guarded PDF proxy (`/api/documents/pdf-proxy`)**: Enforces `validateUrlForSsrf` (blocking localhost, RFC1918 private networks, link-local `169.254.169.254`, and IPv6 private ranges), restricts hostnames to an explicit educational storage allowlist, and caps streamed size at `44 MB`.
- **Zero committed secrets or binaries**: No API keys, signing keystores, private user data, or `.apk` binaries were committed.

## Remaining Risks & Honest Limitations

- **Physical Android phone not tested in this session**: Native Java additions in `OfflineSyncPlugin.java` (`DownloadManager` + `MediaStore.Downloads`) and `MainActivity.java` (`DownloadListener`) were verified for API-level compatibility (`minSdk 24` / `compileSdk 36`) and mobile JS bundle build, but were **not** installed or executed on a physical Android handset during this session.
- **External Google Drive link availability & size ceiling**: Pre-populated seed documents reference public Google Drive / educational hosts from `nganhangdethi.org` and partner sites. Files larger than `44 MB` exceed serverless proxy memory caps and automatically fall back to Google Drive's embedded preview inside `DkPdfViewerModal` + direct `DownloadManager` / browser download; if an external owner deletes a third-party Drive file upstream, Admin can hide or replace it in `/admin/documents`.
