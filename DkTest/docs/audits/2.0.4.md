## 2. Findings & Root Causes

- **Minigame visuals & social sharing**:
  - Previously, Minigame cards only rendered a thin colored top bar with a single emoji; there was no visual illustration per game, no live preview when Admin created an event, and no Open Graph metadata resolver for `/minigame` or `/minigame/:eventId` (sharing a minigame link on Zalo/Facebook fell back to the generic square `/logo.png`).
- **Voucher banner**:
  - `public/images/voucher-banner.jpg` used loud neon green/gold casino-like coins, fake URL `www.dktest.com`, and an outdated `DEC 31, 2024` date, reducing trust when students shared voucher codes.
- **iOS installation gap**:
  - `/api/app-download` previously only resolved Android `.apk` downloads; opening it on an iPhone/iPad redirected to a `.apk` file that iOS cannot open, and `OpenInAppBanner.tsx` returned `null` for all non-Android devices.
  - Additionally, `api/` already contains 10 serverless functions (Vercel Hobby plan caps at 12), so adding iOS support inside the existing `api/app-download.ts` avoids consuming any additional serverless function slot.

## 4. Firestore Read Budget

- **No additional client Firestore reads**: all minigame artwork metadata and 3-step guides are bundled statically in `minigameAssets.ts`, and all images are served as cached static files (`Cache-Control: public, max-age=86400, stale-while-revalidate=604800`).
- **Social crawler link previews (`/minigame/:eventId`)**: at most 1 single-document read (`minigame_events/{id}`) on `adminDb` (or 1 REST lookup fallback) per uncached crawler request; `/minigame` and `/student/minigame` hub previews perform **0 Firestore reads**.
- **iOS `.mobileconfig` & `/api/app-download`**: **0 Firestore reads** (reads only bundled release metadata + optional cached GitHub Releases API check with 4s timeout).

## 5. Security Boundaries

- **No weakening of Firestore rules, auth checks, or server validation**: `firestore.rules`, `firestore.indexes.json`, and all authenticated backend endpoints remain untouched.
- **Apple `.mobileconfig` safety**: profile contains exclusively a single `com.apple.webClip.managed` payload pointing to `https://dk-test-v3.vercel.app/` with `IsRemovable: true` and `PayloadRemovalDisallowed: false` (no MDM enrollment, no certificates, no VPN/proxy/network restrictions, no device policies).
- **XML & HTML escaping**: dynamic values interpolated into `.mobileconfig` XML and iOS HTML install page are escaped via `escapeXml()` / version character sanitization.
- **No secrets or binaries committed**: no signing certificates, provisioning profiles, `.ipa`, or `.apk` binaries are committed to Git.

## 8. Remaining Risks & Limitations

- **Apple `.mobileconfig` "Unsigned" label**: Because the `.mobileconfig` profile is not signed with a paid Apple Developer / TLS profile-signing certificate, iOS Settings will display "Chưa được xác minh (Not Verified)" during installation. This is standard Apple behavior for unsigned Web Clip profiles; users who prefer zero profile prompts can use Method 2 (Safari → Share → Add to Home Screen) directly.
- **Unsigned `.ipa` sideloading requirement**: Apple iOS does not allow direct installation of unsigned `.ipa` files from Safari without either an Apple Developer Program ($99/year) Ad-Hoc/App Store signature or user-side sideloading tools (AltStore, Sideloadly, TrollStore). This is documented transparently in both `AppInstallModal.tsx` and `/api/app-download?platform=ios&format=html`.
- **Zalo / Facebook OG cache**: Social apps cache `og:image` per URL. Previously shared `/voucher/<CODE>` links may continue showing the old banner until re-scraped or shared with a cache-busting query parameter (`?v=204`).
