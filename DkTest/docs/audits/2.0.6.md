# Audit — DkTEST v2.0.6 (Android versionCode 30)

Date: 2026-11-26  
Git branch: `main`

## Scope

Comprehensive 6-pillar platform upgrade requested by the user:
1. **Course Resource Unlock Rules (ON/OFF & Scopes)**: Configurable ON/OFF automatic unlock for course materials and/or linked exams when a student unlocks video(s), defaulting to at least 1 video in the topic (`any_video_in_topic`), plus `same_lesson`, `full_topic`, `full_chapter`, and `full_course`.
2. **Minigame Schedule, Realtime Chat & 3 New Lively Games**: Admin-configurable start/end/duration/reveal timers, zero-Firestore-read realtime chat (`minigame_chat` via RTDB + API fallback), and 3 new interactive welfare games (`lucky_wheel`, `treasure_flip`, `mystery_box`) with 1200×630 artworks.
3. **Remake Subject Preview Banners**: Minimalist, bright, vivid, thumbnail-legible redesign of all 14 subject banners (+ aliases) in `public/images/subjects/`.
4. **Functional Exam Cognitive Levels (`NB / TH / VD / VDC`)**: End-to-end editing, matrix & filtering in Exam Builder, sub-exam filtering & exact matrix picking (`allowedLevels`, `levelCounts`, `by_level`), ExamIntro matrix preview, and ExamResult charts & filter chips.
5. **Smarter & Fully Autonomous Admin AI Agent**: Subfolder-aware, Vietnamese diacritic-insensitive existing-folder resolution (eliminating duplicate folder creation), live folder tree injection into AI context, and 10 new autonomous admin actions covering folders, exams, cognitive levels, courses, minigames, and notifications.
6. **Mandatory Force-Update, Fixed Android APK Signing Conflict & Persistent User Login Across Updates**: Non-dismissible updates on Android & Web/PWA, deterministic persistent APK keystore signing across CI/local builds (no secrets committed), and 3-tier on-device user session persistence (`localStorage` + `IndexedDB` + Android Keystore AES-256-GCM).

## Root Causes & Findings

- **Course resources**: Previously `buildCourseHierarchy` gated every material/exam strictly by `st.canWatch` on its own lesson, with no ON/OFF toggle or topic/chapter/course scope, and `getAuthorizedLessonContent` rejected requests unless the specific lesson's video was unlocked.
- **Minigames**: Previously limited to 5 games with no event start/end scheduling or room chat (only ephemeral emoji cheers).
- **Subject preview banners**: Previous banners shared a dark `#090d16` slate background with small 14px pills and dense footer chrome, making subjects hard to distinguish at thumbnail size.
- **Cognitive levels**: `QuestionEditor.tsx` only edited legacy `difficulty` (`easy`/`medium`/`hard`) and never synced `level` (`NB`/`TH`/`VD`/`VDC`), while sub-exams and result charts ignored cognitive levels altogether.
- **Admin AI Agent duplicate folders**: Both `AdminAIAssistant.tsx` (`resolveOrCreateTargetFolder`) and `folderService.ts` (`organizeExamsIntoFolders`) filtered out subfolders (`if (f.parentId) return false`), lacked Vietnamese diacritic/prefix normalization, and never showed the live folder tree to the model — causing repeated creation of duplicate folders.
- **Android APK package conflict on update**: `.github/workflows/dktest-android-release.yml` ran `./gradlew assembleDebug` on ephemeral runners with no persistent keystore, causing Gradle to generate a new random debug certificate on every CI run. Android refuses in-place upgrades when signing certificates differ, forcing uninstall (which wiped WebView storage and logged users out).

## Firestore Read & Write Budget

- **Course resource unlock**: **0 extra Firestore reads** — evaluated purely from the already-loaded `course.lessonOutline` and `access` document.
- **Minigame realtime chat & schedule**: **0 Firestore reads/writes for chat** — live messages use Firebase Realtime Database (`minigame_chat/$eventId`) with an in-memory server ring-buffer API fallback (`/api/minigames/:id/chat`). Schedule fields are stored inside the existing `minigame_events/{id}` document.
- **Cognitive levels**: **0 extra Firestore reads** — derived from already-loaded exam questions and submission answers.
- **Admin AI Agent folder tree context**: Cached in-memory for 30 seconds (`folderSnapshotCacheRef`), avoiding repeated folder scans across consecutive prompts.
- **Force-update check**: 1 lightweight HTTP JSON request to `/api/app-download?format=json` throttled to every 10 minutes (**0 Firestore reads**).
- **User session persistence**: Purely on-device (`localStorage` + `IndexedDB` + Android Keystore file) — **0 extra Firestore reads**.

## Security Boundaries

- **Paid course video protection preserved**: In `server/services/courseService.ts` (`getAuthorizedLessonContent`), when a student is granted access to a lesson's materials or linked exam via topic policy (`any_video_in_topic`) without having unlocked that specific video, the server strictly returns `videoUrl: ""` so paid video links can never leak. Free preview videos do **not** unlock paid resources of other lessons in `any_video_in_topic`.
- **Firestore rules untouched**: No Firestore security rules were weakened. Only Firebase RTDB `database.rules.json` gained `minigame_chat/$eventId` mirroring existing `minigame_cheers/$eventId`.
- **Zero committed secrets or keystores**: No `.jks`/`.keystore` files, passwords, or service-account keys were committed to Git. CI supports GitHub Secrets (`DKTEST_ANDROID_KEYSTORE_B64`, `DKTEST_ANDROID_KEYSTORE_PASSWORD`, `DKTEST_ANDROID_KEY_ALIAS`, `DKTEST_ANDROID_KEY_PASSWORD`) with an isolated `actions/cache@v4` fallback, and local builds store the keystore under `%USERPROFILE%\.cache\dktest-android\dktest-signing.jks` outside the repository.
- **Native session encryption**: On Android, `user-profile-snapshot.json` and `offline-auth.json` are encrypted at rest with AES-256-GCM backed by `AndroidKeyStore`.

## Deployment & Migration Prerequisites

- **Implemented code vs. deployed production**: All changes in this audit are implemented in the repository on `main`, not yet deployed to production Vercel / Firebase / GitHub Releases until pushed and CI completes.
- **Firebase RTDB rules**: Deploy `database.rules.json` (`firebase deploy --only database`) so `minigame_chat/$eventId` works natively on Firebase RTDB (until deployed, `MinigameRealtimeChat` gracefully falls back to `/api/minigames/:id/chat`).
- **Permanent Android CI Signing Key (Recommended)**: Add repository secret `DKTEST_ANDROID_KEYSTORE_B64` (base64-encoded JKS) + optional `DKTEST_ANDROID_KEYSTORE_PASSWORD`, `DKTEST_ANDROID_KEY_ALIAS`, `DKTEST_ANDROID_KEY_PASSWORD` so the signing certificate never expires from GitHub Actions cache (7-day eviction policy if idle).
- **One-time Android transition from `<= v2.0.5`**: Because older CI APKs (`<= 2.0.5`) were signed with ephemeral random debug keys, users upgrading from `<= 2.0.5` to `v2.0.6` will need **one final uninstall + fresh install** of `v2.0.6`; all subsequent upgrades (`v2.0.6 -> v2.0.7+`) signed with the same persistent keystore will install in-place without package conflicts and preserve saved login state.

## Remaining Risks & Honest Limitations

- **Physical Android device / APK installation NOT tested in this session**: Gradle APK compilation and physical phone installation (`adb install`) were not run on a physical Android device in this environment; Java changes in `OfflineState.java` / `OfflineSyncPlugin.java` and `android/app/build.gradle` will be compiled by GitHub Actions (`.github/workflows/dktest-android-release.yml`) on push.
- **GitHub Actions cache eviction**: If `DKTEST_ANDROID_KEYSTORE_B64` secret is not set and no Android build runs for >7 days, GitHub Actions may evict the cached keystore; configuring the secret makes signing permanently immutable.
- **WebView session recovery on reinstall**: If a user manually uninstalls the app (rather than upgrading in-place), Android deletes app-private files (`filesDir` and WebView storage) by OS design. In-place upgrades (now enabled via persistent signing) preserve all 3 storage layers automatically.
