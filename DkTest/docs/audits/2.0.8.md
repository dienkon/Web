# Audit — DkTEST v2.0.8 (Android versionCode 32)

Date: 2026-11-27  
Git branch: `main`

## Scope

1. **Dedicated Ngân Hàng Đề Thi Folder & Authentic Multi-Level Folder Explorer**: Create a dedicated root folder for **Ngân Hàng Đề Thi (`nganhangdethi.org`)** (`sfold_nhdt`) and manage the entire Document Library as an authentic hierarchical folder tree (matching each original source's category/menu structure, plus preserving nested `<li class="folder_ft">` subfolders inside multi-file packs).
2. **Clean Separation of Spaces (`Độc quyền DkTEST` vs `Cộng đồng` vs `Nguồn gốc`)**: Keep **Tài liệu Độc quyền DkTEST (`dktest_exclusive`)** cleanly separated in its own showcase and tab so official DkTEST materials are never buried by external aggregated repositories.
3. **Contributor Custom Folders & Update Studio**: Allow uploaders (both Community Contributors and Admins) to create their own custom folders & nested subfolders (`library_folders`), upload single or multi-file packs directly into folders, bulk-move documents between folders, and edit/update both folders and documents anytime.
4. **Whole-Folder & Multi-File Batch Download ("Cho phép tải toàn bộ")**: Implement a zero-dependency UTF-8 PKZIP archive builder (`zipBuilder.ts`) and batch download engine (`batchDownloadService.ts` + `BatchDownloadModal.tsx`) supporting both single-file `.ZIP` downloads (preserving nested Vietnamese subfolder paths) and sequential native/browser downloads while strictly skipping locked paid items.
5. **Expand Multi-Source Repository (`tailieuonthi.edu.vn` & `tailieuonthi.org`) & Optimize Payload**: Harvest documents and authentic category trees from `https://tailieuonthi.edu.vn/` (THCS 6–9, THPT 10–12, ĐGNL, ĐGTD) and `https://tailieuonthi.org/` (THPT, HSA, TSA, V-ACT, SPT, QDA), expanding the pre-populated repository to **5,402 documents** across **280 active folders** while splitting multi-file pack payloads (`document-library-packs.json`) for fast initial load.

## Root Causes & Findings

- **Flat catalog overload**: Mixing thousands of external scraped documents into one flat stream without source root folders and without separating `Độc quyền DkTEST` made source-specific browsing harder. Introducing `space` (`dktest_exclusive` | `community` | `sources`), `LibraryFolder` trees, and dedicated source root folders (`sfold_nhdt`, `sfold_tlo_edu`, `sfold_tlo_org`, `sfold_math_partners`) restores crisp organization.
- **Nested internal folders on `nganhangdethi.org`**: Multi-file posts on `nganhangdethi.org` encode nested subfolders via `<div class="folderTree_ft">` (`<li class="folder_ft">...<ul><li class="file_ft">`). Parsing the `<ul>/<li class="folder_ft">` stack preserves exact `folderPath` hierarchies across **480 nested packs** (912 total multi-file packs).
- **WordPress REST + Native v2 APIs on `tailieuonthi.edu.vn` & `tailieuonthi.org`**:
  - `tailieuonthi.edu.vn` exposes its 66-category hierarchy via `/wp-json/wp/v2/categories` and direct Google Drive PDF links inside `/wp-json/wp/v2/posts` (**912 documents** harvested, including THCS Grades 8–9).
  - `tailieuonthi.org` exposes its 79-category hierarchy via `/wp-json/wp/v2/categories` and structured download targets (`Tải đề thi`, `Tải đề kèm đáp án chi tiết`, `bundle_items`, `teacher_word_url`) via `/wp-json/tailieuonthi/v2/resource/<id>` (**772 documents** harvested).
- **Payload size optimization**: Storing 35,000+ sub-file entries directly inside the main catalog JSON would inflate initial download to `5.58 MB` raw. Splitting sub-file arrays into a lazy-loaded `public/data/document-library-packs.json` keeps `public/data/document-library-seed.json` at **~457.4 KB gzipped** (`2,190.8 KB` raw) even after adding +1,222 new documents and 280 folders.

## Firestore Read & Write Budget

- **Browsing, navigating 280 folders & searching 5,402 seeded documents**: **0 Firestore reads** — computed in-memory (`buildFolderTreeIndex` in `<3ms`) from static CDN `/data/document-library-seed.json`.
- **Opening a multi-file pack (`912` seeded packs)**: **0 Firestore reads** — lazy-loaded once from static CDN `/data/document-library-packs.json`.
- **Live custom folders & live uploads (`GET /api/documents/live`)**: Both `library_documents` and `library_folders` are cached in server RAM for **45 seconds** (`LIVE_DOCS_TTL_MS`) and client RAM for **30 seconds**, invalidated immediately on mutation.
- **Batch Download resolution (`POST /api/documents/batch-resolve`)**: Uses 0-read server seed cache fast-path for all seeded `doc_*` items, and queries `library_entitlements` at most **once per batch** (not once per file) when checking paid live documents.
- **Social crawler previews for folders (`/documents?folder=sfold_...`)**: Resolved from server's in-memory seed folder map (**0 Firestore reads**); live `lfold_...` folders perform **1 single `doc.get()`**.

## Security Boundaries

- **Folder ownership & cycle protection**:
  - Non-admin users can only create/edit/delete folders in `space == "community"` where `ownerUid == actor.uid`, and can only nest subfolders or place/move documents inside folders they own.
  - `assertValidParentChain` enforces cycle detection and caps folder nesting at `MAX_FOLDER_DEPTH = 6`.
  - Direct client writes to `library_folders` are blocked in `firestore.rules` (`allow write: if isAdmin();`); hidden folders (`status == 'hidden'`) cannot be read by anonymous or non-owner clients.
- **Batch download paid-content isolation**: `resolveBatchAuthorizedDocuments` verifies ownership, admin role, or active `library_entitlements` before returning URLs from `library_document_secrets`; locked paid documents are skipped (`skippedLockedCount`) and never leak secret URLs.
- **ZIP path-traversal & proxy protection**: `sanitizeZipEntryPath` strips `..`, null bytes, and drive prefixes; `fetchProxiedPdfBuffer` enforces `validateUrlForSsrf`, an explicit educational domain allowlist, a `44 MB` per-file ceiling, and rejects `text/html` error/login pages so HTML is never saved as a binary document.
- **Zero committed secrets or binaries**: No API keys, signing keystores, private user data, or `.apk` binaries were committed.

## Remaining Risks & Honest Limitations

- **Physical Android phone not tested in this session**: Mobile Web/Capacitor assets and native `saveBase64ToDownloads` (`application/zip`) / `DownloadManager` integration were verified via automated tests and production builds, but `DkTEST-2.0.8-debug.apk` was **not** installed or executed on a physical Android handset during this session.
- **Batch `.ZIP` memory & file-size ceiling**: Client-side `.ZIP` assembly caps each batch at `60` documents / `80` files and `44 MB` per proxied file to stay safe within mobile WebView memory and serverless proxy limits. Very large Ebooks (`>44 MB`) or direct Google Drive folder links (`gdf:...`) are automatically reported in the batch summary so users can download them via individual native/direct mode.
