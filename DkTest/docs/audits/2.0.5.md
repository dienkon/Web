## 1. Scope

1. **Fix Matching Table (`matching` / "Nối bảng") missing, frozen, or stripped across Editor & Preview surfaces**:
   - Unlock interactive matching board editing in **Xem trước & Sửa song song** (`ExamVisualPreviewEditor.tsx` left pane) and separate **Hiện đáp án đúng** vs **Ẩn đáp án** in the right Live Paper preview with CSS `zoom` / `transform` SVG coordinate compensation.
   - Render full interactive 2-column editing and live board preview in **Soạn văn bản (Chia đôi)** (`DualPaneSplitEditor.tsx`) and implement lossless 2-way text serialization/parsing in `dualPaneTextParser.ts`.
   - Render matching table previews & answer keys in collapsed `QuestionCard.tsx`, `ExamPreviewModal.tsx`, `ExamPreExamSolutionPreviewModal.tsx`, `SubmissionDetail.tsx`, `StudentTutorialResult.tsx`, Word `.doc` export (`wordExportService.ts`), and Print HTML / LaTeX `.tex` export (`latexExportService.ts`).
   - Fix JSON import data loss in `normalizeExamJson.ts` and `ExamToolbar.tsx` (`processImportedJsonData`).
2. **Mobile-friendly Matching UX (`InteractiveMatchingBoard.tsx`)**:
   - Eliminate the `onPointerDown` + `onClick` self-cancelling tap bug that prevented tap-to-select on touchscreens and mouse clicks.
   - Isolate pointer drag gestures (`touch-action: none`) strictly to 36×36px anchor handles so vertical page scrolling over question text never misfires connections.
   - Add bidirectional tap-to-connect (Cột 1 ➔ Cột 2 or Cột 2 ➔ Cột 1), inline quick-pick target buttons right under the selected card, and a 1-tap **Ghép nhanh ĐT** full-width mobile card layout mode for long formulas and passages.
3. **Configurable Connection Rules (`one_to_one` vs `multiple`) & Unconnected Distractor Cells**:
   - Allow per-question configuration between **Chỉ 1 ô – 1 mạch (`one_to_one`)** (at most 1 wire per cell in both columns) and **Cho phép 1 ô nối nhiều mạch (`multiple`)** (1-to-many and many-to-many connections).
   - Allow unconnected distractor cells in Cột 1 and/or Cột 2 ("Không nối"), safe label remapping on row deletion, and fair edge-based grading with anti-spam protection.

## 2. Findings & Root Causes

- **Broken editor & preview surfaces**:
  - `ExamVisualPreviewEditor.tsx` passed `isReview={true}` to the left editor's `<InteractiveMatchingBoard>`, causing all click/drag handlers (`if (readOnly || isReview) return;`) to exit immediately so teachers could not wire answers on the board. On the right Live Paper preview, `isReview={true}` with `correctMatches` caused dashed green answer guides and red error pills to stay visible even when **Ẩn đáp án** (`showCorrectAnswers === false`) was active, while CSS `style={{ zoom }}` shifted `getBoundingClientRect()` line coordinates relative to local SVG space.
  - `DualPaneSplitEditor.tsx` only rendered a static `"X cặp đã ghép nối"` stub with no columns or board preview, and `dualPaneTextParser.ts` did not serialize or parse `matching` questions — syncing text converted matching questions back into empty `single_choice` cards.
  - `ExamPreExamSolutionPreviewModal.tsx` and `SubmissionDetail.tsx` had no rendering branch for `q.type === "matching"`, showing only the question prompt without the 2-column table.
  - `normalizeExamJson.ts` (`normalizeQuestion`) fell through to `else { q.type = "single_choice"; ... }` for `matching`, `ordering`, `fill_blank`, and `essay`, wiping matching data during file JSON import; `ExamToolbar.tsx` (`processImportedJsonData`) similarly omitted `matchingLeft`, `matchingRight`, and `correctMatches`.
- **Mobile interaction failures**:
  - In `InteractiveMatchingBoard.tsx`, `onPointerDown` immediately called `setSelectedLeft(label)`, and when the user lifted their finger on a tap, `onClick` saw `selectedLeft === label` and immediately toggled `selectedLeft` back to `null`, breaking tap-to-connect. Meanwhile, `onPointerDown` on the entire card conflicted with touch page scrolling, and `grid-cols-2 gap-8 p-4` left only ~75px of text width per column on 360px phones.
- **Unconnected cells & row deletion bugs**:
  - Setting a Cột 1 row's dropdown to `-- Chọn --` stored `{ "3": "" }` in `correctMatches`. `gradingService.ts` counted `"3"` in `Object.keys(correctMap)` while requiring `String(userVal).trim() !== ""` AND `=== ""`, making a 100% score mathematically impossible whenever any row was left unconnected.
  - Clearing all pairs in `MatchingEditor.tsx` (`Object.keys(question.correctMatches).length === 0`) immediately reset `correctMatches` back to `DEFAULT_CORRECT_MATCHES`.
  - Deleting a middle row in Cột 1 or Cột 2 relabeled items `1..n` / `a..z` without remapping surviving keys/targets in `correctMatches`, leaving orphan keys and shifted answers.

## 3. Summary of Changes

- **Core Engine & Schema (`src/utils/matchingUtils.ts`, `src/types/index.ts`, `src/utils/json/schema.ts`, `src/utils/json/normalizeExamJson.ts`, `src/services/ai/aiSchema.ts`)**:
  - Added `MatchingMode` (`"one_to_one" | "multiple"`) and `MatchingConnections` (`Record<string, string | string[]>`), storing single targets as plain strings (100% backward compatible with existing Firestore documents and V3 JSON files), multi-targets as `string[]` (Firestore-safe map of arrays, no nested arrays), and omitting unconnected keys cleanly.
  - Implemented `resolveMatchingMode`, `toggleMatchConnection`, `setLeftTargetsInMode`, `removeMatchWire`, `getUnconnectedItems`, `removeLeftItemAndRemap`, `removeRightItemAndRemap`, and `gradeMatchingQuestion`.
  - Fixed `normalizeQuestion` in `normalizeExamJson.ts` to preserve `matching`, `ordering`, `fill_blank`, and `essay` fields during JSON import/migration.
- **Mobile & Multi-Mode Board (`src/components/exam/InteractiveMatchingBoard.tsx`)**:
  - Fixed tap-to-connect state machine with bidirectional selection (`Cột 1 ➔ Cột 2` and `Cột 2 ➔ Cột 1`), isolated drag-to-connect onto dedicated 36×36px `touch-action: none` anchor handles, added inline quick-pick target strips below selected cards, added the **Sơ đồ dây / Ghép nhanh ĐT** layout toggle, added `isAnswerKeyPreview` mode, and added CSS `zoom`/`transform` scale compensation for SVG lines.
- **Editors, Previews, Grading & Exports**:
  - Updated `MatchingEditor.tsx`, `ExamVisualPreviewEditor.tsx`, `DualPaneSplitEditor.tsx`, `dualPaneTextParser.ts`, `QuestionCard.tsx`, `ExamEditorContext.tsx`, `ExamToolbar.tsx`, `ExamPreviewModal.tsx`, `ExamPreExamSolutionPreviewModal.tsx`, `StudentTutorialExam.tsx`, `StudentTutorialResult.tsx`, `TakingExam.tsx`, `ScratchpadModal.tsx`, `ExamResult.tsx`, `SubmissionDetail.tsx`, `LiveMonitor.tsx`, `QuestionMapNavigator.tsx`, `attemptAnalytics.ts`, `gradingService.ts`, `wordExportService.ts`, `latexExportService.ts`, and `chatGptMasterPrompt.ts`.

## 4. Firestore Read Budget

- **0 additional Firestore reads or writes**:
  - `matchingMode` (`"one_to_one" | "multiple"`) and `correctMatches` (`Record<string, string | string[]>`) live inside the existing embedded `questions` array on `exams/{examId}` (or `exams/{examId}/questions/{qId}` for paid exams) and `answers` map on `submissions/{subId}`.
  - All normalization, mode inference, preview rendering, and grading run purely in memory with zero extra network or Firestore queries.

---

## 5. Security Boundaries

- **No weakening of Firestore rules, RTDB rules, or server auth checks**: `firestore.rules`, `database.rules.json`, and backend auth/entitlement guards remain completely unchanged.
- **Answer key stripping preserved in Live Proctoring**: `TakingExam.tsx` continues stripping `correctMatches` before syncing `sanitizedQuestionsForLive` to RTDB, exposing only `matchingLeft`, `matchingRight`, and `matchingMode` (`"one_to_one" | "multiple"`), never leaking answer keys.
- **Anti-spam grading protection**: `gradeMatchingQuestion` deducts excess wires (`max(0, userTargets.length - correctTargets.length)`) from net hits, preventing candidates from gaming multi-connect or distractor questions by connecting every cell to every option.
- **No secrets, keys, APKs, or `dist/` / `dist-mobile/` bundles committed** (only tracked source files, tests, metadata, and synced `server/*.bundled.js` route modules referenced by `api/*.ts`).

## 7. Deployment Prerequisites & Production Distinction

- **Implemented vs Deployed**:
  - All source code, schema updates, unit tests, and release metadata (`v2.0.5`, `androidVersionCode: 29`) are implemented and committed on `main`.
  - Production web (`https://dk-test-v3.vercel.app`) updates automatically once pushed to `origin/main` and deployed by Vercel.
  - Android APK (`DkTEST-2.0.5-debug.apk` / GitHub Release `dktest-v2.0.5`) requires running `npm run android:apk` or triggering the release workflow before mobile APK users receive `versionCode 29`.
- **Backward Compatibility**:
  - No database migration is required: legacy matching questions without `matchingMode` automatically infer `"multiple"` if their `correctMatches` contain multi-targets or shared right targets, and default to `"one_to_one"` otherwise; legacy empty-string `""` entries in `correctMatches` are normalized cleanly as unconnected distractors.

## 8. Remaining Risks & Limitations

- **Real-device touch verification**: Although the `onPointerDown`/`onClick` collision bug was root-caused and fixed, drag handles now use `touch-action: none`, and both inline quick-pick pills and full-width **Ghép nhanh ĐT** mode were added, actual thumb ergonomics on physical iOS Safari and Android WebView handsets were **not** manually tested in this Windows CLI session and should be spot-checked after deployment.
- **Very dense multi-connect wire diagrams**: When a teacher creates a `multiple`-mode board with many crossing wires (e.g., 8×8 items with 20+ simultaneous connections), the 2-column SVG wire view remains functional but visually dense; students on small screens can switch to **Ghép nhanh ĐT** or read the color-coded pills on each row for unambiguous clarity.
