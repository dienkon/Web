## 1. Scope

- Sửa triệt để lỗi endpoint `/api/app-download` (và hộp thoại cập nhật trên App/Web) trả về phiên bản cũ `1.9.14` thay vì phiên bản mới nhất đã phát hành trên GitHub Releases.

---

## 2. Findings & Root Causes

- Kiểm tra trực tiếp `https://dk-test-v3.vercel.app/api/app-download?format=json` trả về `version: "1.9.14"`, `androidVersionCode: 20`, `releaseDate: ""`, trong khi GitHub Releases đã có sẵn `DkTEST-2.0.0-debug.apk`.
- Nguyên nhân: `src/services/server/appDownload.ts` chỉ đọc `path.join(process.cwd(), "release.json")` và gán cứng fallback `{ version: "1.9.14", androidVersionCode: 20, date: "" }`. Khi hàm serverless trên Vercel không tìm thấy `release.json` tại `process.cwd()`, nó rơi về `1.9.14` rồi tìm đúng tag cũ `dktest-v1.9.14` trên GitHub Releases và trả về `exactReleaseFound: true`.
- Tương tự, `src/services/appLinks.ts` cũng gán cứng fallback `'1.9.14'` / `20`.

---

## 3. Summary of Changes

- `scripts/generate-html-template.js` & `src/services/server/generatedReleaseMeta.ts`: tự động đồng bộ `release.json` thành hằng số TypeScript `GENERATED_RELEASE_META` mỗi lần chạy `npm run build` để Vercel serverless luôn đóng gói sẵn metadata phiên bản mới nhất.
- `src/services/server/appDownload.ts`:
  - `readCurrentReleaseJson()` dò nhiều đường dẫn (`import.meta.url` tương đối, `process.cwd()/release.json`, `process.cwd()/DkTest/release.json`) và fallback sang `GENERATED_RELEASE_META` (loại bỏ hoàn toàn chuỗi gán cứng `1.9.14`).
  - `resolveAndroidApkDownload()` so sánh semver giữa các bản phát hành có tệp `.apk` trên GitHub Releases và luôn ưu tiên bản phát hành cao nhất (`>= rel.version`).
- `src/services/appLinks.ts`: thay fallback gán cứng `'1.9.14'` / `20` bằng `GENERATED_RELEASE_META`.
- Cập nhật `release.json` (`2.0.1`, `androidVersionCode: 25`), `README.md`, `CHANGELOG.md`, `docs/audits/2.0.1.md`.
