# Code Studio

Open **Luyện tập → Code Studio**, `/practice/code` or `/student/practice/code`.
The IDE has its own full-screen route so the site navigation does not consume mobile editing space.

- Desktop: Monaco Editor, IntelliSense for web languages, diagnostics, snippets, find, undo/redo and bracket matching.
- Touch mode: highlighted native textarea, contextual completion chips with expandable details, automatic indentation, symbol keyboard and visual-viewport resizing when the phone keyboard opens. Toggle touch mode in Settings.
- Projects: file/folder tree, nested paths, create/rename/move/delete, tabs, multiple local projects, automatic browser storage, full project ZIP export, separate JSON backup/restore and individual file download.
- Upload: **Tải file code lên** accepts multiple UTF-8 programming/config/text files directly, including HTML/CSS/JS/TS/Python/C++/Java/Go/Rust/Vue and ordinary JSON. **Tải thư mục lên** preserves paths below the selected folder. Review the batch, then create a new project or add files into an existing project/folder. Collisions are rejected unless replacement is explicitly selected. Invalid paths, binary/non-UTF-8 files and oversized batches are rejected before changing the project. The JSON backup restore button remains separate. Current limits are 100 files and 1 MB of source/metadata per project.
- Web preview: HTML with relative CSS/JS, nested CSS imports and local JavaScript ESM imports, explicit HTML entry selection, phone-width preview, optional auto refresh and console forwarding. No bundler, npm resolution or TypeScript transpilation is included.
- Self-contained HTML: embedded `<style>`, `style` attributes, classic/inline module `<script>` and event handlers stay in the document and run in preview/shared website mode. Embedded styles can import local CSS too. Running a selected HTML tab uses that file as the preview entry, even when the project contains another HTML page. Uploading a standalone HTML creates an HTML-only project by default; it does not require separate CSS/JS files.
- Python: Pyodide in a worker, STDIN, project-local Python imports.
- C/C++: JSCPP interpreter for basic teaching exercises, STDIN and local quoted header includes. Not a GCC/Clang toolchain; advanced STL/C++ standards are unsupported.
- JavaScript-only projects: asynchronous console execution in a worker; `prompt()` reads the prepared STDIN lines. DOM code belongs in a web project.
- Prettier: HTML, CSS, JS, TS, JSON and Markdown, with optional formatting after typing. Python/C++ indentation is preserved.

## Workspace controls

- Drag a file or folder using its grip (`⋮`) into another folder; drop on the project heading, empty tree space or the root drop zone to move it to the root. Touch/pen uses the same grips without hijacking normal tree scrolling. Dragging near tree edges scrolls the list. Escape cancels a drag. Moving a folder moves its entire subtree, preserves file content and active/entry pointers, retains empty source folders and rejects collisions or moving into descendants. Relative imports/HTML links are not automatically rewritten after moves.
- The item menu also offers **Di chuyển tới thư mục…**; press Enter/Space on a grip for the keyboard equivalent. Select a folder, then use the file/folder buttons to create inside it; each folder menu supports creating both files and subfolders.
- Preview can dock above, right or below the editor, or become a floating window. Drag split separators to resize docked panes; use arrow keys when a separator is focused. Floating previews can be dragged by the header grip, resized from the bottom corner, minimized and maximized. The grip/corner also accepts arrow keys. Pane changes keep the same iframe, preserving website interaction state. Mobile portrait starts with preview above the editor; landscape starts side by side. Both panes remain visible, with touch separators and compact controls. Floating preview remains available. On supported mobile browsers the first trusted touch inside the workspace requests native fullscreen; browsers that reject or lack the API keep the full-viewport layout. The header also has a fullscreen toggle. Keyboard opening shrinks the workspace and hides secondary chrome.
- Console includes optional local-clock timestamps and completion details: execution duration (worker-measured, excluding runtime loading) and total elapsed time (including setup). Error, cancellation, initialization timeout and execution timeout are distinct. Web previews report readiness time on page load. C++ output fragments are buffered into readable lines, and Python/JS retain line breaks; bounded output is flushed before completion/errors.
- Monaco skips the touch-highlighting work, and editor renders are memoized so dragging panes, moving the cursor and console updates do not redo syntax highlighting. Auto-preview responds to source/entry changes, not merely switching tabs.

## Sharing and persistence

New shares use short stable project links such as `/code/trang-web-cua-ban.0123456789abcdef` with three modes:

- **Chỉ website**: immediately opens the interactive website, without IDE or editing controls. Only rendered HTML and required local assets are included. Browser-delivered HTML/CSS/JS remains inspectable with developer tools.
- **Website + cho sửa**: opens the website with an option to edit an independent local copy.
- **Dự án / IDE**: opens an independent editable local copy without automatically executing it.

Each local project has one current share URL. The server derives its document ID from the verified Firebase UID and local project ID; it preserves the first slug and creation timestamp. Republish replaces content, title, mode and cover in that document instead of creating a new URL. Renaming the project/title keeps the same URL. Duplicated projects and editable recipient copies have new local project IDs and therefore independent links. Closing/reopening the dialog retains mode, title, description, Cloudinary cover and URL locally. If a publish response or local binding is lost, the server still derives the same ID on retry.

Editing, project management, AI requests, opening the share dialog, capturing a cover and reading a shared link do **not** write to Firebase. Only **Tạo link chia sẻ & sao chép / Cập nhật link & sao chép** calls `POST /api/code-studio/shares` (after an optional Cloudinary cover upload). Continuing to edit stays local until republishing. Public JSON/HTML use `Cache-Control: no-store` so reopening a link reads the latest published version. This is explicit publication, not live collaboration. Local project deletion does not revoke a published link.

Existing `/s/:slug` links remain readable; locally saved share bindings migrate to `/code/` without changing their document ID. Legacy fragment links and old immutable cloud snapshots remain readable. They were created without a verified owner, so they cannot safely be claimed/overwritten. The first publish using the new system establishes one owner-bound stable link; subsequent publishes reuse it. Existing legacy links remain snapshots.

The dialog extracts `<title>` and meta description from the entry HTML. A preview cover is optional: publish immediately without one, or capture/select an image and remove it with **Bỏ ảnh**. Image processing remains local until explicit publishing. On publish, a selected/captured JPEG uploads to Cloudinary using the existing cloud name and unsigned preset in `src/services/cloudinary.ts`; Firebase stores only the returned HTTPS `imageUrl`. Failed uploads can be retried or skipped by removing the image. A successful upload is reused if Firebase publication needs a retry while the dialog remains open. Capture first executes the page in an opaque sandbox, then renders a static script-disabled snapshot using pinned html2canvas 1.4.1. Cross-origin images require CORS; canvas/video, WebGL and complex CSS may need a custom cover. No user code executes in the application origin. JPEG covers are 1200 × 630. `/code/:slug` serves title, description and OpenGraph/Twitter image metadata directly in server HTML so crawlers need no JavaScript. `og:image` points directly to Cloudinary when a cover exists; no image metadata is emitted without one. `/api/code-studio/shares/:id/image.jpg` still serves legacy stored JPEG covers and redirects new ones to Cloudinary. Both these routes and the JSON read route only read Firebase.

Firebase setup: either configure valid `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` on the server, or apply the checked-in `firestore.rules` collection rule for `code_studio_shares` and configure the existing Firebase REST project/API key. All publishes use a Firebase ID token, verified with Admin Auth or `accounts:lookup`. REST writes forward that token. Rules permit public single-document reads, authenticated creates and updates only by the original UID, keeping owner/project ID/slug/creation timestamp unchanged. List/delete remain denied. Admin writes use a transaction; REST writes use Firestore update-time/existence preconditions to detect races without generating another ID. Rule changes are not deployed by the application.

Signed-in publishers use their existing Firebase account. Guests require the Anonymous auth provider enabled in Firebase; it runs in a separate `code-studio-publisher` Firebase app so it does not change the site's login. Guest authentication starts only on explicit publish. If anonymous auth is disabled, the dialog asks the user to log in. Updating an existing binding requires its original signed-in or anonymous identity; a different account cannot silently create a second link for that binding. Per-process publishing cooldown remains; production-wide quotas/abuse controls require infrastructure configuration.

Publish refreshes the current identity's ID token before sending it. REST verification uses the existing application API-key resolver (`VITE_FIREBASE_API_KEY`, then `FIREBASE_API_KEY`, then the application's default public web key), matching username-login configuration. Missing/invalid keys and provider restrictions return `503 / SHARE_AUTH_SERVER_CONFIG`; actual invalid/expired sessions return `401 / SHARE_AUTH_SESSION`. This avoids telling users to repeatedly log in when the backend key is misconfigured. Verification failure never falls back to trusting an unverified UID or writing anonymously. Logs include only provider status/category, never tokens, keys or account payloads.

Up to 20 local projects, 100 files and 100 explicit folders per project, 1 MB source/metadata plus up to 80 MiB of remote media per local project. Cloud source payload limit is 700 KB; optional Cloudinary image URLs are bounded to 2048 characters. New shares never store image bytes in Firestore. Legacy JPEG snapshots remain readable. Storage/quota errors are visible; export remains available. Corrupt existing storage is preserved instead of silently overwritten.

## Mobile editing, projects and AI

Mobile always keeps physical code lines unwrapped with horizontal scrolling. Textarea, syntax layer and gutter share identical line metrics and scroll offsets. HTML tags auto-close on typing `>` (excluding void/self-closing tags, comments and raw script/style text); Enter between a tag pair inserts an indented blank line. Desktop uses Monaco plus the same HTML closing guard.

Touch suggestions recognize HTML tags/attributes/relative file paths, CSS properties/values, JavaScript/TypeScript members and snippets, Python/C++ snippets and identifiers from project sources. They also detect embedded HTML script/style contexts. The compact chip rail expands to show details; touch keeps the keyboard open. Arrow keys select, Tab accepts, Enter accepts only an explicitly selected suggestion, Escape closes. IME composition is preserved. Suggestions use bounded local source scans and do not call AI or Firebase.

**Tải ảnh / video** immediately uploads the selected media to the existing Cloudinary unsigned preset, independently of sharing. Supported images: JPEG/PNG/GIF/WebP/AVIF; video: MP4/WebM/MOV. Limits: 8 MiB/image, 25 MiB/video, 10 files and 50 MiB per batch, 80 MiB total media/project. File headers, paths and response metadata are checked. The preset in `src/services/cloudinary.ts` must permit the selected media types and CORS downloads. Successful files are retained when a later upload fails; retry uploads only the remaining files. Project files retain Cloudinary URLs and metadata locally; no Firebase write occurs. Preview resolves relative media paths in HTML attributes, srcset and CSS URLs. Dynamically assigned JavaScript URLs can use the copyable Cloudinary URL.

**Xuất dự án** downloads a UTF-8 ZIP containing every source file, empty folder and the actual downloaded image/video bytes at their project paths. It keeps source contents unchanged, supports progress/cancel and rejects missing/failed media instead of silently leaving files out. A ready download link stays visible if automatic browser download is blocked. Archives are limited to 100 MiB; individual fetched media to 30 MiB. JSON backup/restore remains separate and retains remote URLs rather than binary media.

**Quản lý dự án** searches, opens, renames, duplicates, exports and deletes local projects. Delete requires confirmation and never deletes published links.

**AI lập trình** uses exactly `gemini-3.5-flash-lite` through `POST /api/ai/code-studio`. Set server-only `GEMINI_API_KEY`, or enter a personal key in the AI panel (the existing device-local key preference). A request sends the current project only after explicit submit; it does not write Firebase. Structured responses apply complete changed files atomically, reject invalid paths, and detect files edited while the request was running. One-step undo is available until subsequent file changes would make restoration unsafe. Stop/timeout never applies a late response. Provider access, model availability and billing depend on the supplied Gemini key; no live paid model request is part of automated verification.

## Runtime isolation and downloads

Preview and runtime frames use `sandbox="allow-scripts"` without `allow-same-origin`. Runtime workers are created inside an opaque frame, not in the application's origin. CSP prevents application API access from programs. Preview permits public JavaScript from cdn.tailwindcss.com, cdn.jsdelivr.net and cdnjs.cloudflare.com, CSS from those hosts and fonts.googleapis.com, and font files from fonts.gstatic.com/jsDelivr/cdnjs. Application-origin scripts and API connections remain blocked. Static cover capture permits the same CSS/fonts with scripts disabled. Website-only snapshots receive the current preview policy on read, including old fragment/cloud links, without modifying the stored snapshot. Preview messages must match the current frame and per-run token. Runtime initialization times out after 90 seconds, execution after 10 seconds, and the Stop button tears down the frame/worker. Output is bounded.

No package installation or backend compiler is required. Pinned Monaco 0.52.2, html2canvas 1.4.1 and Prettier 3.6.2 load from jsDelivr on demand; Python uses Pyodide 0.27.7; JSCPP uses upstream commit `76e3534f04abf9c2547aa73ddca275e8935bed38`. These features require CDN connectivity. The Prism touch editor is bundled and remains available when Monaco cannot load.

## Verification

`npm run lint`, `npm test`, `npm run build`.
`tests/codeStudio.test.ts` covers project validation, Unicode sharing, independent copies, path traversal, collisions, limits, rename propagation, language detection and local ESM path rewriting.
`tests/codeStudioWorkspace.test.ts` covers file/folder moves, empty parent preservation, collision/descendant rejection, viewport bounds, duration formatting and execution of the worker with async timing, buffered C++ output and errors.
`tests/codeStudioImport.test.ts` covers standalone HTML source preservation, multiple language/config uploads, directory structure, entry selection, UTF-8/binary/path/size validation and atomic collision/replacement handling.

Browser smoke checks: desktop editor and Prettier, interactive HTML/CSS/JS preview and console, cross-origin storage isolation, C++/Python/JS execution with STDIN, mobile tree/suggestions/preview, and opening an editable shared copy without executing it. Workspace checks include actual mouse/touch dragging, nested creation, collision/cancellation, move dialog, both split resize directions, floating drag/resize, minimize/maximize without iframe remount, runtime timing/error/stop, and mobile overflow checks.

`tests/codeStudioEditingAi.test.ts` covers HTML editing, AI response validation, conflict-safe application and exact provider model selection. `tests/codeStudioCloud.test.ts` verifies stable URL reuse, ownership, race preconditions, legacy reads, failure handling, metadata escaping and payload validation using a mocked Firebase transport.

Production API verification: after `npm run build`, run `node scripts/verify-code-studio-api.mjs`. It transpiles only the Vercel entry and loads it with plain Node (without tsx extension resolution), verifies cold-start imports, rewritten publish/read/metadata routes and JSON errors, and uses an in-memory Firebase transport. The build emits `server/codeStudioRoutes.bundled.js` just like the existing API route bundles.

`tests/codeStudioMobileUpgrade.test.ts` covers contextual completions and stale ranges, media validation and metadata preservation, AI media protection and complete ZIP source/media/folder export with cancellation/failure handling. Browser smoke uses intercepted Cloudinary responses (no real uploads), checks touch split resizing and portrait/landscape/short layouts, fullscreen, media preview resolution and actual ZIP download; Python zipfile independently verifies CRC and file bytes.
